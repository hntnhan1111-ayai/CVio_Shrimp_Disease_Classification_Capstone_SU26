# Experiment Protocol

## Merged result selection

The integrated package is a merged best-by-dataset archive, not a single-method rerun.
Within each dataset, the highest Macro-F1 is selected and accuracy breaks ties. The common
display label is retained alongside the verified source method, label-match flag, and
checkpoint hash. Combined-4's selected 87.73% accuracy / 86.51% Macro-F1 result is CE
Baseline; ShrimpDB-3's 91.49% / 91.29% result is ASL-LDAM + SimAM-DCFR.

This document describes the dataset split protocol, the rationale for the source-wise then
partition-wise union approach, and reproducibility considerations for the
**shrimpdb_combined_multisource** study.

## 1. Split Protocol Overview

All experiments use a stratified **70% train / 15% validation / 15% test** split with
**random seed 42**. Stratification is performed per class within each data source, ensuring
that the class distribution is approximately preserved across splits.

The split ratio 0.70 / 0.15 / 0.15 was selected as a standard distribution for moderate-sized
image classification datasets, providing sufficient training data while maintaining a test set
large enough for stable per-class metric estimation.

## 2. Source-Wise Split Then Partition-Wise Union

The two experiments in this study involve datasets from different sources (ShrimpDB and
ShrimpDiseaseDB) with different class spaces. To maintain scientific rigour, the split was
performed in two stages:

### 2.1 Stage 1: Source-Wise Split

Each dataset is split independently before any class harmonization or union:

1. **ShrimpDB** is split into train / val / test at the 70/15/15 ratio (seed 42) within its
   three harmonized classes (`Healthy`, `BG`, `WSSV`).
2. **ShrimpDiseaseDB** is split independently at the same ratio (seed 42) within its four
   classes (`Healthy`, `BG`, `WSSV`, `WSSV_BG`).

This ensures that no image from ShrimpDiseaseDB appears in the ShrimpDB test set and vice
versa, preventing data leakage between sources.

### 2.2 Stage 2: Partition-Wise Union

After source-wise splitting, the partitions are concatenated across sources:

- Combined-4 **train** = ShrimpDB-3 train + ShrimpDiseaseDB train
- Combined-4 **val** = ShrimpDB-3 val + ShrimpDiseaseDB val
- Combined-4 **test** = ShrimpDB-3 test + ShrimpDiseaseDB test

This approach ensures that every image in the Combined-4 test set originates from a held-out
split of its respective source dataset, and no source dataset's test images appear in
training or validation partitions.

### 2.3 Rationale

The source-wise-then-union approach was adopted for the following reasons:

1. **Prevents cross-source data leakage**: If splits were performed on the combined dataset
   without source-wise stratification, images from ShrimpDiseaseDB could leak into the
   ShrimpDB training partition, artificially inflating test performance.
2. **Enables source-domain analysis**: Because each source maintains its own test partition,
   performance can be evaluated separately per source, supporting the source-domain analysis
   reported in this study.
3. **Maintains class balance across sources**: The union preserves the per-class counts
   documented in the dataset tables, which reflect the true relative class frequencies across
   both sources.

## 3. Split Manifest

The complete split manifest is generated by `02_prepare_splits.py` and stored at:

```
artifacts/experiments/{experiment}/manifest.csv
```

Each entry records the image path, source dataset, original label, harmonized label, and
split assignment (train/val/test).

## 4. Reproducibility Notes

- The split is **deterministic** given the fixed random seed of 42. Re-running
  `02_prepare_splits.py` with the same seed and dataset versions will reproduce the exact
  same partition assignments.
- The `deterministic: true` flag in the training configuration requests PyTorch deterministic
  algorithms where available. Note that complete determinism across hardware generations and
  CUDA versions is not guaranteed by PyTorch.
- Split manifests are committed to the repository; raw images are not. Reproducers must
  download the datasets from Kaggle using the slugs provided in `configs/study.yaml` and run
  `02_prepare_splits.py` to regenerate the manifests.

## 5. Image-Level Splitting Limitation

The split is performed at the **image level** without established specimen or animal identity.
Images that originate from the same physical specimen may appear in both training and test
partitions. This is a known limitation of the current protocol, and future work may consider
specimen-level splitting if unique identifiers are available.
